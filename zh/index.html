    刘泽文 -- 研究与项目¶

    我研究多 Agent 大语言模型系统。简单说，就是当好几个 AI 模型互相通信的时候，它们的输出会发生什么变化。

    这不是一个抽象的问题。当你用 GPT-4o 和 DeepSeek 搭一个多 Agent 系统时，如果 Agent A 读到了 Agent B 的回答，它下一次的回答会变得更像 Agent B。这种"传染"效应会影响系统的所有输出，而且很难被发现。

    我的工作是：测量这种效应有多强、什么时候发生、怎么阻止它。

    三个核心发现¶

    发现一：通信有两面性¶

    以前有人研究过"多个 AI 会不会达成共识"，也有人研究过"一个 AI 的错误会不会传染给另一个"。但没有人同时测量过这两件事。

    我们在同一个实验里同时测量了"策略共识"（Agent 的回答变得相似）和"校准传染"（一个 Agent 的评估误差传播到其他 Agent）。用了一个叫 CAF 的指标。

    具体数据： 在 GPT-4o 上，30 个 Agent 一组，约 9,900 次 API 调用。文本通信让 Agent 之间的相似度增加了约 20%（CAF = 0.803，95% 置信区间 [0.740, 0.873]）。

    一个重要细节： 效应的方向取决于 Agent 的数量。5 个 Agent 时通信导致它们变得更相似；3 个 Agent 时通信可能导致它们变得更不同。所以不能笼统地说"通信会怎样"，要看具体系统参数。

    发现二：概率校准不是万能药¶

    很多人以为，给 LLM 的输出做概率校准（比如 Platt Scaling 或 Temperature Scaling）就能解决评估噪声问题。我们在 60 种不同条件下测试了这个假设。

    结果是：有时候校准确实有用，有时候没用，有时候反而让情况变糟。效果取决于你用什么模型、喂什么数据、用什么协议。

    这意味着你不能假设校准一定能改善系统。你需要针对自己的具体设置做实验验证。

    发现三：评估存在"不可能三角"¶

    我们猜测 LLM 评估有三个互相矛盾的属性：偏差（评估者偏离真实值的程度）、可靠性（评估者的一致性）、耦合（评估者受被评估 Agent 影响的程度）。这三个属性不可能同时最优——改善其中一个必然会恶化另一个。

    这就像分布式系统的 CAP 定理，或者机器学习里的偏差-方差权衡。你需要根据应用场景选择牺牲哪个属性。

    我们测试了 11 种不同的评估者-Agent 条件，发现了支持这个猜想的一致性 tradeoff 模式。
